Cookie Tracker Graph Workflow

A presentation workflow for a proof-of-concept that crawls website cookies, transforms them into a site-domain-cookie graph, exposes the graph through a FastAPI backend, and visualizes the relationships in an interactive Deck.gl + Mapbox frontend.

Phase 1 — Brief & Scope
01

Receive PoC Brief

Confirm the goal of the PoC: whether the client wants cookie inventory, third-party tracking visibility, consent comparison, request flow analysis, or a relationship intelligence demo.

Client Requirement PoC Scope Demo Objective
02

Identify Target Sites & Pages

Select public websites or demo URLs to crawl, then define whether the scan covers the homepage only or multiple flows such as landing, product, checkout, and consent entry points.

Public URLs Target Pages Scan Plan
03

Choose Tech Stack

Use Playwright for browser automation, FastAPI for backend APIs, JSON as the interim data layer, and Deck.gl + Mapbox Dark for the interactive relationship intelligence stage in the browser.

Playwright FastAPI Deck.gl Mapbox Dark
Phase 2 — Crawl & Extract
04

Open Site in Browser Context

Launch a controlled browser session, load the selected website, wait for the page to stabilize, and prepare the browser context for cookie inspection and request capture.

Browser Context Page Load Session Start
05

Capture Cookie Metadata

Read cookies from the browser context and capture fields like cookie name, domain, path, expiry, secure flag, httpOnly flag, sameSite behavior, and inferred category.

Cookie Read Metadata Security Flags
06

Store Raw Scan Output

Save the raw crawl result in a reusable JSON file so the same cookie scan can feed the backend, graph builder, waterfall analysis, and demo frontend without rerunning the crawl every time.

cookies.json Reusable Output Data Snapshot
Phase 3 — Transform & Model
07

Normalize Cookie Records

Clean the raw cookie structure and standardize fields so every record can be transformed consistently into graph nodes, risk indicators, consent summaries, and vendor summaries.

Normalization Field Cleanup Consistent Schema
08

Build Site-Domain-Cookie Graph

Create graph nodes for the scanned site, domains, cookies, vendors, and categories, then connect them with relationships that expose first-party and third-party tracking structure.

Graph Nodes Graph Edges Relationship Map
09

Prepare Summary Metrics

Compute counts for total cookies, domains, third-party links, vendors, high-risk records, and category spread so the frontend can present a fast executive view before exploration.

Cookie Count Domain Count Risk Summary
Phase 4 — Backend API
10

Expose REST Endpoints

Return summary data, graph data, and dashboard-supporting payloads through API endpoints so the frontend can load only the panels it needs.

/summary /graph /dashboard
11

Enable Frontend Access

Configure local API access, CORS behavior, and environment variables so the dashboard can fetch cookie intelligence data reliably during development and demo sessions.

CORS Localhost Frontend Fetch
Phase 5 — Frontend Demo
12

Load Dashboard Summary

Display KPI cards for total cookies, domains, third-party exposure, vendors, high-risk records, and unknown classification to establish the top-level intelligence view.

KPI Strip Dashboard Quick Metrics
13

Render Interactive Map Stage

Use Deck.gl and Mapbox Dark to render the site-domain-cookie-vendor-category relationships as an interactive intelligence stage where users can zoom, pan, and inspect structure visually.

Graph Canvas Interactive Nodes Map Intelligence
14

Inspect Details & Lower Panels

Let the user review node details, anomalies, vendor concentration, category spread, request waterfall, and consent classification in supporting panels under the main stage.

Details Panel Risk Panels Interactive Review
